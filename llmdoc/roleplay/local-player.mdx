# 独立游玩页面与launch交接

独立游玩 app 是 named dsh profile 的显式 opt-in 组合；React 包仅提供 private 静态产物，没有另一条应用 launcher。Host 持有 Registry/OAuth、模型和 Session 服务，浏览器只消费 type-only app-types DTO 与同源 API，不导入 Host 的执行实现。共享 util/crypto 为浏览器生成可恢复请求ID，不能改用仅安全上下文可用的临时UUID方案。

静态文件在激活时从声明的浏览器包载入，只服务明确列出的产物，不以请求路径读取任意文件。页面 bootstrap 仅含本实例 nonce 与 Registry origin；Host 同时核对 Host、Origin、nonce 和 JSON 类型，页面/接口不缓存，打包的指纹资源可缓存。启动监听不依赖 Registry discovery；首次API/回调按需连接，连接失败可在下一次明确操作重试。Dispose 中止连接与活动操作、释放server并等待在途请求，不能在卸载后继续授权或派发。

来自 char.pub 的 tokenless launch envelope 只描述精确来源、locale、视角和开局，不能覆盖本地模型/Registry配置。审阅rating、许可、能力与角色绑定后才创建新的日志；刷新dbld必须重新交接并解释新开局，不能把新产物覆盖旧Session。来源仍由真实Registry读取与SDK摘要验证。

列表经持久化公共接口按页识别roleplay日志，unreadable条目保留可诊断状态，不把存储路径发给页面；record handle用于选择本地记录，active session handle用于实际操作，两者不互换。Resume重新读取精确Registry来源、核产物与授权后恢复已提交投影，不重新开场。旧页签、旧授权或另一个活跃Session的handle不能把输入转投新会话。

启用 play 时，每次用户发送固定 request_id、原文本与当前 expected_revision，普通对白和场景可自动规划，省略 play 的 profile 保留旧显式输入入口。结果未知先查询该请求，不立即换 ID 重发；确认 not_found 后才允许显式按原 ID 重试，持久 pending 则按 Runtime 恢复规则处理，刷新不重发模型。取消只请求停止，已结算回复仍可能被保存；配置中的模型名不证明凭据或在线模型已验证。

页面使用 SDK 的 projectPlayerView 展示玩家身份、当前场次、在场 NPC 公开画像、已知资料、可用选项与已达成公开进展，不从 narrator 的私有目标或原始变量构造面板。阶段提案单独等待玩家按钮确认，提交 opaque proposal ID 和最新 revision；只有 listed 结局预先显示标题/说明，hidden 与 on-reach 只显示触发输入。确认保留未发送草稿，不代发草稿或执行投稿/发布；成功后的正式进展与待确认提案分开显示。

对白保存与剧情判定结果分别呈现，恢复请求也保留剧情判断不可用和 superseded 提示。撤回以 revision 防旧状态操作，恢复上一成功回合且保留历史；Host 更换活动 handle 使旧页签失效，响应未知时先恢复状态，不连续盲点撤回。

未发送草稿和待查请求按record保存在tab-local session storage，界面语言/主题是本地偏好，不改变Story locale或日志。Synthetic导出使用独立空的摘要和绑定表单，不自动复制私聊/游玩角色私描述；审阅与下载是两个动作，服务端仍重核head。用户自选的Story状态也可能含秘密，不能把白名单导出称为全无敏感内容。

真实宿主验收需要实际观察启动、OAuth、来源review、角色绑定、恢复、窄屏与浅深背景的可操作性；DOM/health成功不足以证明可玩。首选新tab失败时平台可选择同tab交接，仍使用原精确信封与守卫，不传token或正文。
