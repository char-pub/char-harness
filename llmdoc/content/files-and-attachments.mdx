# 附件、spill与交付

附件、spill 和交付共同处理内容生命周期，但身份与用途不同。附件引用需要对应可持久读取的字节；spill 保存调用方的大输出；present/交付表达用户可以取走的产物。临时 URL 不是可永久回放的内容身份。

应先满足字节持久性再记录依赖它的事件，否则日志可能引用从未保存成功的文件。Spill 的原文归调用方，不应被后续展示组件静默重写；格式转换也要说明生成物与原始资料的关系。

修改内容路径时检查取消、丢失、清理和重启后的读取，并分别验证模型、UI 与交付消费者。文件名、具体格式清单和转换参数留在当前实现，避免另一份过期目录。
