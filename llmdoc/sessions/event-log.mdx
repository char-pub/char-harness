# Session事件、surface与fork

Session 的 append-only event log 是持久事实；模型消息、聊天气泡和轨迹都是按消费者需求得到的 surface。新增模型可见输入必须能由已记录事实解释，不能另存一份无来源的 shadow history 再称它为同一次请求。

哪些事件属于模型 surface 是语义决定，不由事件是否存在或 UI 是否展示推断。Fork 必须明确继承的历史和新身份，不能回写父 Session。Repair 同样需遵循日志与代际规则，不能通过覆盖旧字节消除失败证据。

改事件时先确认是否真的需要 durable fact、谁追加、谁投影和旧 reader 如何拒绝未知必需事件。持久格式迁移由 durability owner 审查；纯显示变化不应顺手改变事实记录。
