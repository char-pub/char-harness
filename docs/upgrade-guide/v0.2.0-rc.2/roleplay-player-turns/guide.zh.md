# 持久化玩家回合

[English](guide.md) | 中文

## 变更

实验性角色扮演运行时支持作者声明的玩家控制、受约束回合决策与只追加的撤回。新玩家回合在叙述前保存意图、精确决策请求和结果。新增必需事件将这些尝试绑定到原始逻辑 head 与持久事件 revision。纯 Replay 操作追加一条输入和有序、经 Core 校验的动作；叙述成功后一起提交。既有显式命令和已保存的 Session 仍可按其固定 SDK 输入读取。

打包 SDK 包含可选的 `Story.player` 声明；使用该声明的内容要求 `story.player-control` 能力。运行时输入据此使用 SDK 的精确 participant 身份。没有该声明的旧内容保留原有用户消息行为。声明不会重新归属旧历史，也不表示运行时 `user` 绑定指向某个演员。

新玩家回合把符合条件的结局保留为绑定状态的提案，等待显式确认。可选提案/确认元数据属于新增回合事件；既有命令和缺少此元数据的旧回合保留已记录行为与精确摘要。提案在重启、失败尝试和检查后保留，成功普通回合会替换或清除它。确认跳过后续决策，只请求一次叙述，并仅在成功时提交终局效果。

## 迁移

1. 更新运行时前备份 Session 文件并保留原始 SDK manifest。先对副本运行 Session 检查；运行时不会重写既有条目、摘要或开场输入。
2. 配置明确的生成与决策路由，以及最低置信度、动作数、整回合决策调用数和 token 限额。玩家文本/选项使用 `play`，保留同一客户端请求 ID 和最新 `revision`。既有 `submit` 调用者可继续使用显式命令。
3. 写入玩家回合前升级所有读取器。旧读取器无法解释新增必需事件，必须拒绝读取；不得将事件改成可忽略或删除后继续。若返回写入前备份及匹配的旧运行时，应将其视为独立历史。
4. 中断后先检查原请求。重复已完成 ID 返回其存储结果，未完成 ID 永远不会再次派发。通过带 `recover_interrupted: true` 的新 ID 显式结束旧尝试。不能因为写入失败或取消就推断已回滚。
5. 使用观察到的 revision 调用 `rewind`，恢复上一条成功玩家回合之前的状态。撤回保留原事件和幂等记录。随后刷新玩家视图与操作句柄；旧 revision 不能创建新分支，已被撤回的请求 ID 不能重新应用效果。

6. 仅渲染待确认提案的公开字段。发送 `confirm_ending: { proposal_id }` 时使用新 ID、确认文本和最新 revision；不得提交私有结局目标或把确认与选项合并。不确定的确认结果通过原 ID 核对。撤回确认会恢复此前的提案，再次确认前应刷新。
