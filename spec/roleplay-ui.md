# char-harness 游玩界面

状态：实施设计。用户在2026-10-01明确要求重新设计Harness UI。本文件确定本轮产品范围与可验证行为；会话、模型与精确内容规则仍由现有Runtime及公开char.pub SDK负责。

## 使用者与主要任务

主要使用者是从char.pub选择角色或剧情、希望进入故事并继续对话的人。主路径是选择作品→确认开局与扮演身份→开始或继续本地会话→回复。连接服务、模型设置、授权恢复和导出是辅助任务。界面不要求用户理解JSON、内容摘要、Session事件或Provider实现。

内容和游玩分工保持：char.pub创作与发布静态内容，Harness持有本地会话、生成请求、决策与日志。浏览器不持有模型密钥，不复制领域求值或上下文编排算法。现有Jev/Laya库保留；未在当前app启用的自动剧情判断不得画成可用开关。

## 信息组织

桌面采用三部分：左侧会话列表和新故事入口，中间对话及固定回复区，右侧当前作品/角色/场景资料。窄屏保留对话，将会话列表与故事资料变为可打开并关闭的面板，面板不会遮挡或丢失回复草稿。

- **会话**：仅列真实本地记录，显示作品名、最后活动及可恢复状态；空列表明确从char.pub开始。选择会话通过后端重新验证记录及源内容，不能只是前端切换旧缓存。
- **对话**：标题、当前场景、可读的角色名称；区分玩家输入和角色/旁白输出。回复框支持多行、清楚的发送与停止按钮。发送中保留已输入内容，完成后才清除；失败保留可编辑草稿及具体恢复动作。
- **故事资料**：使用本轮视角允许的角色与场景信息，避免默认展示其他角色的秘密或全局状态。精确版本、能力限制、来源与技术诊断放入展开区域。当前界面没有自动剧情动作时明确说明，不展示无效的分支推进控件。
- **连接与设置**：显示Registry与模型各自的实际状态。已配置提供方不等于验证过密钥，更不等于线上可用。无可靠检测时显示“尚未验证”，不能显示绿色“已连接”。模型凭据继续由既有本机配置持有；设置页给出真实配置指引和重试操作，不建设第二个凭据存储。

## 第一次进入与作品接入

无launch、无本地会话时展示简短欢迎和可点击的char.pub入口，列出从作品页或草稿进入的方法及当前Runtime地址。默认隐藏手动launch JSON，保留在高级入口。没有作品不能出现可以开始游玩的假状态。

接到launch后先加载实际产物，显示作品名、说明、评级、许可和必须知道的能力限制。通过表单选择开局、当前视角和角色绑定；名称、公开描述与私有设定有明确解释，内部ID只在高级信息里出现。多开局与锁定视角按真实数据处理。确认绑定当前审阅摘要，内容或授权变化须重新审阅。

已有会话时，打开另一版本或草稿明确创建新会话，保留旧记录。恢复本地会话读取原日志并重新验证其来源；过期或撤权要解释原因，不能静默换到最新版本。

## 请求与恢复

不模拟流式输出。当前driver只提供完成结果时，使用真实发送中状态与最终回复；只有后端提供真实增量后才显示增量文本。取消作用于明确的会话和请求，不保证抹去已经落盘的结果。

客户端为一次发送保存请求ID；未知网络结果使用同一ID核对或重试，不偷偷生成新请求重复调用模型。旧标签页不能向后来切换的会话误发。断线、授权失效、源构建过期、缺少模型配置及普通服务错误分别有可理解提示，输入不会无声丢失。

已存会话列表必须有界，不为每次打开页面无界读取全部日志。列表与UI状态从真实持久数据/当前运行状态推导，不保存另一套剧情事实。取消、重载和恢复沿用既有Session事件和历史代，不改写已有日志。

## 视觉与交互

整体使用安静的暖白/深色背景、明确文字对比和克制的橙色主操作，优先阅读剧情。用排版、留白和角色头像/首字区分发言，不把开发者表单堆满主界面。所有页面明确设置背景与前景，避免嵌入宿主的透明底色影响可读性。

交互文案归属有类型的语言字典，首版提供中文和英文；语言选择只改变界面，不暗改会话内容的locale或已锁定配置。按钮具有可见标签、键盘焦点和禁用原因；加载、空、错误、无权限与恢复有完整状态。任何成功提示必须来自实际已提交结果。

## 实现组织

新增私有静态前端`apps/roleplay`，使用仓库现有React/Vite版本；它不提供Node bin或第二个应用服务器。现有named dsh profile仍加载roleplay app，在同一loopback服务提供静态资产及API，保留Host/Origin/nonce校验。前端只消费浏览器安全的类型化DTO。

保留现有app controller、Registry OAuth客户端和roleplay Session driver的职责。现有coding Web shell解释agent-loop事件，直接复用会引入不匹配的历史和依赖；本轮复用可适用的视觉/可访问性原则，不挂入coding loop，不复制其完整UI框架。后端补会话列表/恢复与准确状态，所有语义仍来自Runtime和SDK。

## 验收

1. 无作品的新标签页可以找到char.pub与配置说明，不需粘贴JSON。
2. 从真实char.pub草稿进入、授权、选择开局与角色后，显示真实开场和清楚的回复区。
3. 本地历史列表可恢复代表会话；过期、撤权、旧tab、未知请求结果均不误导或改写历史。
4. 固定网络替身验证真实发送、取消、失败和恢复；没有模型凭据时不宣称已通过在线生成质量。
5. 在用户当前浏览器、窄屏和浅/深主题下实际查看页面，确认主路径可点击、文字可读、焦点可见且回复草稿保留。
6. 通过本仓相关类型、构建、实际profile/HTTP/浏览器与持久历史检查；不能以只返回HTTP200完成验收。
