# Agent Note: 角色扮演回合事务

Status: implemented

[English](2026-10-05-roleplay-turn-transactions.md) | 中文

## 问题

一条玩家输入可能包含多个作者声明的 Story 动作。在本次输入进入 judge 前确认动作，会丢失判定证据；在叙述前提交动作，会让回复失败后事实仍已改变。撤回后复用逻辑 head，还可能让旧标签页把另一条事件历史误认为自己观察过的状态。

## 决策

[运行时](../../../../packages/experimental/charpub-roleplay-runtime/README.zh.md) 在准备一个原子 Replay 回合前，记录意图、每次决策输入及结果。配置的模型只能提议作者声明的目标 ID 和类型化判定。Core 负责条件与效果；叙述成功后，一起发布输入、已校验动作和助手响应。含糊决策保持未确认。决策推理留在私有流证据中，应用另外投影玩家可见进展。

持久 revision 对完整事件前缀取摘要，与逻辑 Replay head 相互独立。撤回追加事实，恢复上一条成功回合之前的逻辑状态，同时保留旧请求及结果。已被撤回的 ID 仍视为已使用。未完成尝试只能由带新 ID 的显式恢复请求结束，永远不会自动再次派发。

结局符合条件与结束游玩的授权相互独立。导演可以保留一个绑定状态的提案，但只有新的显式确认才能应用其中记录的结局。提案和确认都与叙述原子提交；失败保留此前提案和状态。公开字段遵循作者声明的 reveal 策略，私有记录保留原决策提供方。确认以手动身份复用原判定值，不再询问导演或选择器。撤回把此前提案作为同一记录逻辑状态的一部分恢复。记录指导版本，使结构化确认的新澄清与历史措辞分离：回放会重建模型可见指令，直接修改无版本文本会让既有请求摘要失效。无版本 JSONL 样本保留提案、确认和撤回字节；在版本 2 中，普通同意仍仅是提案证据。

原子叙述使用独立必需事件 `roleplay/turn-requested`，旧 `roleplay/requested` 的命令和证据类型保持固定。这保留已接受的 Session 类型，让旧读取器拒绝新事实，不会静默解释扩大的命令联合类型。[升级指南](../../../../docs/upgrade-guide/v0.2.0-rc.2/roleplay-player-turns/guide.zh.md) 负责操作迁移说明。

不可变 ReplayCursor 完整校验一次外部日志，随后基于冻结的当前准备结果前进。运行时投影仅通过自己创建的不可变 Replay 日志与游标建立弱关联，外部可变日志永远不成为缓存键。这样在一次 Session 折叠中消除重复完整 Replay 重建，无需信任调用者改动的状态，也不保留每一步的重建输出。每次新读取 Session 仍校验持久事件，不存在独立持久状态缓存。

## 考虑过的替代方案

**先提交推断效果再生成。** 回复被拒绝或中断时，动作与可见对话会不同步。保留待提交状态让成功结算成为统一发布边界。

**自动应用符合条件的结局。** 格式正确的模型判定也可能把问题或试探行为误认为终局承诺。显式确认让玩家决定这一剧情内不可逆选择，同时保留普通进展自动处理。增加决策推理额度可以改善结构化答案的完成情况，但增加延迟与 token 成本，也不能消除语义误判。

**仅用逻辑 head 做并发和幂等判断。** 撤回可能返回之前的 head。包含失败尝试和撤回的 revision 能在逻辑状态重复时继续阻止陈旧操作。

**扩大旧 requested 载荷。** 持久化分类器会正确要求对其未版本化命令联合类型做全局写入版本升级。新必需事件把兼容性变化限制在可选角色扮演功能内。

**延长超时或缓存整个可变 Replay 结果。** 三十条合成回合暴露重复规范化、摘要和 Schema 解析，原路径在第 14 回合超时。冻结游标消除了重复工作；提高超时只会保留这些工作，可变结果缓存则可能掩盖改动并保留所有展开步骤。

**因一条多余叶子而废弃全部判定。** 提供方可能正确回答作者问题，同时额外返回一个结构条件路径。只有已声明的 target/path 对能成为 Core 证据；未声明条目被忽略，重复仅让自身叶子弃权。这样保留独立有效证据，不解释未知判定，也不降低置信度要求。

## 后果

意图识别仍可能出错，置信度只是模型报告值，不是校准后的事实。Core 拒绝不可用目标，撤回允许修正已结算回合。私有 Session 包含决策输入、流、原始文本和全部分支；删除、修剪、跨进程 checkpoint 和长历史分页仍是独立工作。

归属测试比较游标与完整 Replay 的结果，保留历史样本字节，覆盖全部五个写入屏障，并通过真实 Loader 与 JSONL 服务验证多动作失败、取消、恢复和陈旧 revision。固定三十回合的源代码加载诊断在游标改动后完成了 60 次本地模型派发；其耗时不含真实网络或模型延迟，不证明浏览器表现或生产容量。消息 snapshot 保留相同的准备内容。测试与日志回放负责这些校验，不另建可变不变量缓存。

真实 JSONL 检查还覆盖待确认结局、重启、hidden/on-reach 信息披露、陈旧提案 ID、确认失败及中断、重复请求恢复、撤回与历史自动结局回放。官方适配器 HTTP fixture 检查实际 profile overlay 的独立模型路由、低强度决策思考与关闭叙述思考。这些确定性检查验证运行时行为，不证明在线模型质量。
